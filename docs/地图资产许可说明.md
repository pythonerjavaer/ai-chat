## CRS 与使用边界

[GeoNames 官方导出文档](https://download.geonames.org/export/dump/readme.txt)明确经纬度为 WGS84，并说明数据没有准确性、及时性或完整性保证。GeoNames 点在每条记录中标为 `crs: "WGS84"`；记录保留 GeoNames ID、原始参考点链接与修改日期。

Supeset 原始 GeoJSON 未声明 CRS。本项目没有将其推断为 WGS84 或 GCJ-02，也没有进行未经依据的坐标转换；整个边界集合及每个边界要素均为 `crs: "unknown-display"`。它们是原始坐标形态的展示边界，不是符合 RFC 7946 坐标约定的已确认 WGS84 GIS 数据。边界中心同样不因经纬度数值看起来合理而获得 WGS84 身份。

GeoNames 点与未知 CRS 的展示边界叠合仅供行政地区示意；不承诺二者精确重合，不用于导航、测绘、地址距离计算或点在多边形内判定。坐标是行政／城市参考点，不是行政机关门址、企业总部、招聘岗位办公地址或用户所在地。只有逐条 `crs == "WGS84"` 的点允许作为确认的地理经纬度或写入 Neo4j SRID 4326；13 条未匹配到可信点的记录保留 `unknown-display`，不得写成 SRID 4326。

岗位地理映射只能依据岗位公开的明确地点字段及其行政上下文；不能据企业名称猜总部或推断个人所在地。同名、矛盾和不足以确定上级的地区应标记为歧义或未映射，而不是强行选中一个点。

## 实际覆盖

- 边界：510 个唯一要素，34 省级、363 源市级、112 区县级及 1 个南海辅助要素；包含香港、澳门、台湾。南海 `100000_JD` 几何原样保留，不是可选地区、岗位点或虚构行政单位。
- 区县边界仅部分覆盖：北京 16、天津 16、上海 16、重庆 38、香港 18、澳门 8；普通省份不具备全国完整区县多边形。源 `city` 层级亦包含一些省直辖县级单位，不应称为 363 个全部同级地级市。
- 目录：3,752 条地区记录，34 省级、386 市级、3,332 区县级；3,739 条 WGS84，13 条 `unknown-display`。补充了 GeoNames 中国大陆 ADM2/ADM3、台湾 ADM2/ADM3 参考点。城市和目录点不能被宣称为完整区县边界。
- 北京、上海、深圳、广州、杭州、成都以及香港 18 区均有已确认来源的 WGS84 参考点和常见英文别名。香港 18 区也都有源多边形。
- 目录保留稳定源行政代码 ID；没有对应边界行政代码的补充条目使用 `geonames:<id>`，不把 GeoNames ID 冒充国家行政区划代码。上级缺失时仅保留可证实的省级上级和 `city_id: null`，不按近邻坐标猜城市。
- GeoNames 快照含旧名称、重复同名行政条目及缺少上级的条目；本目录不是当前、完整、权威行政区划登记册。已知同上下文重复名称保留来源身份，解析须安全处理歧义。不能用记录数量宣称现势性或完整性。

## 文件契约与加载

`frontend/src/data/china-boundaries.json` 为包含 `Polygon`／`MultiPolygon` 的 FeatureCollection；`properties` 含 `id,name,level,parent_id,province_id,province_name,city_id,city_name,center,source,crs,coordinate_precision`。简化保留每个源多边形组件及孔洞数量，不能据此宣称源拓扑无缺陷。约 1.08 MB。

`backend/future_radar/data/china_places.json` 是目录：`schema_version: 1`，顶层 `sources,crs,coordinate_note,coverage,source_snapshot,source_files,places`。逐条含上述行政关系字段、`longitude,latitude,center,aliases,crs,source,coordinate_source,coordinate_precision`；已匹配点另含 `geonames_id,geonames_feature_code,source_modified`。约 2.16 MB，仅后端加载。

`frontend/src/data/china-admin-centers.json` 是供缺边界区县下钻的懒加载精简目录；逐条仅含 `id,name,level,parent_id,province_id,city_id,center,crs,source`。名称和上级显示可按 ID 查询目录。顶层保留来源、许可、CRS、覆盖说明及源快照散列，不包含岗位和个人信息。约 0.72 MB；加上边界约 1.81 MB，均可分别懒加载。

## 可复现生成与验证

使用 Python 3.9+ 与仅构建时依赖 Shapely **2.1.2**。可在隔离临时目录安装 Shapely，然后将其路径传给 `--shapely-lib`；它不成为前端或后端运行时依赖。

```sh
python scripts/prepare_radar_geography.py --source-cache /path/to/reviewed-source-cache --shapely-lib /path/to/build-only-shapely
python scripts/prepare_radar_geography.py --source-cache /path/to/reviewed-source-cache --shapely-lib /path/to/build-only-shapely --check
python -m unittest discover -s scripts -p prepare_radar_geography_test.py
```

源缓存需包含上述两个 GeoJSON 及四个 ZIP。生成脚本内的 `FILES` 为核查的来源 URL 与 SHA256；输出 `source_files` 同样保留它们。固定 Git commit 的边界可再次获取；GeoNames 的下载 URL 每日更新，**并非不可变历史归档**，精确字节复现需要保留经过散列核查的源缓存。脚本遇到新下载快照不会静默改资产，而是拒绝未知散列。

`--refresh-geonames` 是显式使用新快照的审查入口，不是自动现势性认证：使用前需重新审查覆盖、层级、同名歧义、来源散列和日期，更新脚本 `FILES`/`SNAPSHOT`、资产及此说明。不要直接以该选项绕过来源审查后宣称仍为当前核查快照。

生成器先验证覆盖、唯一 ID、上级引用、坐标范围、闭合环、组件／孔洞保留、香港 18 区、核心六城 WGS84 来源及南海辅助几何。`--check` 比较三个输出的完整 UTF-8 字节，且不写文件；静态测试无需网络、数据库或凭据。
