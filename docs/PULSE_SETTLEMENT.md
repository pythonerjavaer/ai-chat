# 脉冲域：租赁结算与往来核销

定位是小型租赁 ERP 与经营决策，不扩展成支付平台。2026-10-21 根据用户的产品范围判断，本轮不实现银行 CSV 流水导入、流水匹配或银行直连。所有“收款/付款”按钮都只登记已实际发生的资金动作，不执行转账。

## 真实业务流程

在“脉冲域 → 结算与核销”打开真实账本。Demo 模式不会读取或修改真实结算记录。

1. 已交付订单可确认剩余租金应收；预约、取消订单不能确认应收。历史已收租金从待确认金额中扣除，不追溯重写既有收入。新应收借记应收账款、贷记租金收入。
2. 应收支持分次收款核销：借现金/银行、贷应收账款，不再确认一遍收入。原交易台的“记录租金”也会识别应收单并走同一核销逻辑。
3. 归还后的订单可用实际剩余押金抵扣租金：借客户押金、贷应收账款；该操作不产生现金流。可用押金扣除历史退款、损坏扣款和租金抵扣；不能超退、重复抵扣。损坏扣款必须有已确认的损坏/缺失检查记录。
4. 先登记供应商及明确未付费用，再生成应付单。费用登记已经借记费用/存货、贷记应付账款；生成应付单只登记未结项，不再重复确认费用。系统检查原应付分录与费用金额一致。
5. 分次支付供应商款项时借记应付、贷记现金/银行，自动更新未付/部分付款/已付状态。历史只标记“部分付款”但缺乏实付金额的记录不会被猜测性核销。
6. 页面展示原额、已核销、未结余额、到期日与逾期标记，并能回查来源订单、应收确认凭证及每笔核销凭证。汇总余额覆盖整个账本，列表每页 30 条；待登记来源最多展示最近 100 条。
7. 误录的核销必须填写原因后冲销：原核销/凭证不删除，生成当前开放期间的反向凭证，恢复应收应付及可用押金，更新费用付款状态；原凭证和冲销凭证双向关联。已关闭原期间或当前期间不自动处理；不同请求并发冲销同一笔时只允许一次。此功能仅更正账务，不执行退款，也不能代替真实退租退款或折让。

## API

所有路由均使用现有用户 JWT，并按 `user_id` 校验来源、科目及单据所有权。

| 方法 | `/api/pulse` 下路径 | 功能 |
| --- | --- | --- |
| GET | `/settlements/overview?page=1&page_size=30` | 余额、单据、未登记来源和现金科目 |
| GET | `/settlements/orders/{order_id}` | 租金剩余应收与押金余额 |
| POST | `/settlements/vendors` | 供应商登记 |
| POST | `/settlements/bills/receivable` | 确认订单剩余应收 |
| POST | `/settlements/bills/payable` | 登记原未付费用的应付项 |
| GET | `/settlements/bills/{id}` | 单据及核销凭证链 |
| POST | `/settlements/bills/{id}/clear` | 按实收/实付金额核销 |
| POST | `/settlements/bills/{id}/deposit-offset` | 归还后押金抵租金 |
| POST | `/settlements/allocations/{id}/reverse` | 填写原因冲销误录核销，保留审计链 |

新写入接口要求客户端稳定的 `request_id`（16–120 字符）。同一编号与相同业务内容重复提交返回原结果；改变金额或业务内容返回 409。原 `/payments`、`/expenses` 兼容已有调用，新增可选 `request_id` 与 `cash_account_code`；新页面及交易台收付款提供请求编号。金额为整数最小货币单位，拒绝布尔和浮点数。账本已有记录后禁止直接切换币种，不提供跨币种重估。

## 一致性、迁移与边界

- 增量创建 `pulse_settlement_bills`、`pulse_settlement_allocations`、`pulse_finance_commands`、`pulse_settlement_reversals`；不批量改写或自动开立用户历史单据。沿用现有应用启动迁移与 PostgreSQL 私有 schema 的权限隔离，不增加 anon/authenticated 的 Data API 授权。
- 金额使用整数最小货币单位；所有新增余额约束与核销金额校验在数据库短事务内完成。SQLite 使用 `BEGIN IMMEDIATE`，生产 PostgreSQL 兼容层对应跨进程事务级 advisory lock；锁内不访问外部服务。来源记录、核销、会计事件、借贷分录与重试回执一起提交，关闭会计期间时整个命令回滚。
- 驾驶舱现金流从现金/银行过账分录计算，纳入供应商分次付款，避免把整张费用账单错误计为当期实付。押金余额从累计负债分录计算，抵租金不再虚增现金流。
- 月度预测仍沿用按实际租金收款月份的历史序列，不把新增应收确认当成现金收入，也不把押金抵扣当作新现金流。
- 冲销后的收款标记为 `reversed`，运营统计与收款月份序列排除错误记录；订单证据及 CSV 保留状态与原记录。会计报表仍按凭证过账日期计算原凭证及反向凭证，跨期间查询时与按有效收款记录计算的运营统计可能不同。同期间的原凭证与冲销凭证先净额合并，再计算驾驶舱流入/流出，避免虚增周转。
- 本轮不是完整财务套件：不含支付渠道/银行转账、银行流水对账、税务发票、外币重估、供应商预付款、退租折让/贷项单或历史非核销收付款的通用冲销。财务报告取决于录入账目与期初余额完整性，不构成审计或税务合规保证。
- 发布前将原20张 Pulse 表以单条 PostgreSQL 查询的一致快照备份为私有本地 JSON，并在隔离的本地 PostgreSQL 恢复逐表逐值校验。备份不是云端 PITR，也不含用户认证库或其他产品数据，不能恢复之后的新交易。
- 回滚应用时保留新增数据表，不提供自动删表迁移。未发生新增金融写入前可恢复上一服务版本；一旦有核销/押金抵扣/冲销，旧版本缺少对应业务语义，不能盲目回滚或用发布前快照覆盖新交易，应停止相关操作并修复前进。
