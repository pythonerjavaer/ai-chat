# 押金覆盖的不确定性评估

按当前用户和费用发生日期，从维修/资产报损记录聚合每张订单的已记录损失；与原有押金覆盖情景共用数据，不把押金当收入，也不自动调整客户押金。

- 业务问题：已记录损失的押金覆盖比例、每笔损失订单平均未覆盖金额，是否受少量客户或极端损失影响？
- 方法：以客户为重采样单元，同一客户的订单整组保留；固定随机种子进行 2,000 次非参数 percentile Bootstrap，显示两项统计量的 95% 置信区间。每次重算比值分母，不平均客户覆盖比率。
- 产品门槛：至少 20 位不同客户、30 笔损失订单且金额有差异；这不是统计充分性的保证。缺客户/订单、重复订单、无效金额或来源截断时不推断。最多 10,000 笔损失订单、2,000 位客户，分批 64 次计算以控制免费实例内存。缩短查询期间可避开上限。
- 解释边界：假设客户间近似独立且所选期间可比，依赖已录入损失的完整性。不包含未录入损失、选择偏差、季节变化与未来业务变化。不是损失发生率、单次未来损失的预测区间、因果分析或自动定价依据。空账本不使用合成数据计算真实置信区间。
- 入口：`GET /api/pulse/analytics` 的 `deposit_coverage.uncertainty`；“经营洞察 → 押金情景”直接展示区间或数据不足原因，无新增数据库表、轮询、外部 API 或付费依赖。

本轮不新增 KDE（已有分位数/箱线图足以表达当前分布）、逻辑回归（缺少完整成熟的前瞻标签及验证集）或 L1/RFE（尚无足够候选特征和稳定的监督学习任务）。不得将这些写入已实现技术栈。Bootstrap 仅用于上述横截面损失严重度分析，未用于月度时间序列误差区间。
